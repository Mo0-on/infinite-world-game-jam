# 《天台夜班》设计文档

**状态**：已与需求方逐轮确认  
**日期**：2026-11-08  
**世界名**：天台便利店  
**类型**：2D 手绘、伪 2.5D、纯鼠标、短流程叙事解谜

## 1. 意图与体验目标

玩家扮演被神秘客人称为“夜班员”的主角，在深夜城市天台便利店完成一次接待，获得传送门图纸，破解仓库锁并按图造门。日常营业员工作逐步转变为跨世界事件，客人身份只通过细节暗示，不直接解释。

目标体验：

- 首次游玩约 3–4 分钟，熟练路线约 3 分钟。
- 玩家始终在理解线索和操作机器，不做自由寻路、战斗或隐蔽像素找物。
- “招待客人 → 获得图纸 → 解锁仓库 → 造门 → 离开”形成一条无分支、无死锁的流程。
- 上一关理智遗物提供合理的跳过增益，但零外部装备仍能完整通关。

## 2. 目标、非目标与反目标

### 目标

- 只制作天台便利店的营业区与仓库，以及设备和图纸近景。
- 两个固定主场景，16:9 构图，支持拖放和“点击物品，再点击目标”。
- 清晰展示小票、价签、图纸、波形与装配反馈。
- 以声音、光线和客人动作完成叙事，不依赖长文本。
- 提供渐进提示和游戏内放弃通道。

### 非目标

- 不制作门后世界，不增加第二个新世界或返回地球后的额外场景。
- 不做自由行走、键盘操作、战斗、死亡惩罚、物品栏整理或多结局。
- 不新增本关跨关奖励道具，不强制生成线索。
- 不建设账号、联网存档、后端服务或通用游戏引擎。

### 反目标

- 没有上一关特定物品就无法通关。
- 客人凭空奖励三个零件、服务与造门成为互不相关的两条跑腿线。
- 固定密码脱离本局小票、无依据试错、错误操作清空全部进度。
- 直接说明客人来自下一世界，或用双月、种族等细节限制下一关创作。
- 长片头、大段任务日志、商业音乐、原生弹窗或第四面墙台词。

## 3. 官方约束

来源：`participant-delivery-kit-v3.3.2/AGENT.md`、`正式交接规则-v3.2.md`。

- 完整正常通关路线不超过 270 秒；前 5 秒无敌意单位或即死机关。
- 主角生命、理智、诅咒和背包来自实际存档，不预设满状态，不伪造或覆盖数值。
- 零外部装备可通关；上游道具只能作为增益或彩蛋。
- 本关零件与图纸是关内道具，不进入跨关声明。
- 本关无新增跨关道具，仍必须提交 `global-items.json`，内容为 `items: []`，通关传 `acquiredItemIds: []`。
- 采用 A 轨 ZIP：`WL.readSave()` 接档，`WL.completeLevel()` 成功交档，`WL.failLevel()` 放弃交档。
- 禁止 `alert()`、`confirm()`、`window.top.location`、`parent.location` 和阻塞式弹窗。
- 不自行决定下一关地址，不打破第四面墙，承接真实 `exit_hook`。
- 投稿 ZIP ≤12 MB，解压后 ≤40 MB，≤250 文件，单文件 ≤35 MB；入口为 ZIP 根目录 `index.html`，资源使用相对路径。
- 音乐、音效与美术必须原创、可商用或合规 AIGC，并按要求申报。

## 4. 技术方案选择

### 方案 A：原生 HTML/CSS/JavaScript + DOM/SVG，A 轨 ZIP（采用）

固定场景、点击/拖放、近景面板和 CSS 动画即可覆盖全部玩法。DOM/SVG 便于控制点击区域、文字清晰度、图纸与波形显示；无框架运行依赖，容易满足包体和沙箱限制。

### 方案 B：Phaser/Canvas，A 轨 ZIP（不采用）

能统一绘制场景和动画，但本次没有物理、寻路或高频战斗，引入引擎与构建配置会增加协作和调试成本。

### 方案 C：GitHub Pages 外链，B 轨 SDK（不采用）

GitHub 只用于代码协作，不作为本次投稿运行方式。外链还需验证长期生产地址、iframe、CSP、CORS 与官方 SDK 握手，当前玩法没有必须外链的理由。

## 5. 流程与状态

主流程状态：

`ARRIVAL → SERVING → BLUEPRINT_RECEIVED → WAREHOUSE_UNLOCKED → ASSEMBLING → READY_TO_CALIBRATE → PORTAL_OPEN → COMPLETE`

放弃可从任意未结束状态进入 `ABANDONED`，通过游戏内二次确认后交档。

### 5.1 开场与接待（目标约 40 秒）

- 一行旁白承接真实 `save.exit_hook`，随后客人说：“夜班员，麻烦结账。”
- 柜台商品：饭团 6 元、咖啡胶囊 4 元、电池 8 元。
- 每件商品只能扫码一次；`receiptOrder` 按实际扫码先后记录商品 ID。
- 咖啡胶囊完成扫码后才能用于咖啡机；错误操作不消耗胶囊。
- 咖啡机操作：放杯 → 放入已扫码胶囊 → 启动 → 将咖啡交给客人。
- 三件商品均扫码且咖啡交付后，进入 `BLUEPRINT_RECEIVED`，客人交出图纸，小票可查看。

### 5.2 仓库密码（目标约 50 秒）

商品价格表固定为：

```text
onigiri = 6
coffee_capsule = 4
battery = 8
```

本局密码按小票顺序拼接：

```text
receiptOrder = ["battery", "onigiri", "coffee_capsule"] → "864"
```

- 仓库锁为三位数字，允许无限尝试，错误只清空本次输入。
- 小票和货架价签均可点击放大，有效数字清晰可读。
- 密码正确后进入 `WAREHOUSE_UNLOCKED`，允许进入仓库。

### 5.3 仓库装配（目标约 80 秒）

- 门框和外部电源已存在，三个组件与三根可拆导管直接可见。
- 组件：`energy`（能源接口）、`stabilizer`（稳定器）、`focus`（聚焦环）。
- 组件可按任意顺序拖放或点击安装到各自轮廓；放错位置时弹回。
- 外部电源已接至能源接口，玩家连接三根导管：
  - `energy → stabilizer`
  - `stabilizer → focus`
  - `focus → frame`
- 图纸显示能量方向；错误连接弹回并高亮对应图纸区域，不撤销已完成步骤。
- 三个组件安装且三条连接正确后进入 `READY_TO_CALIBRATE`。

### 5.4 理智遗物与调频

理智遗物只有官方声明的恢复理智效果，不是能源、钥匙或机器零件，不插入、不消耗。

- 携带时：主角因理智恢复而直接看懂重叠波形，自动完成校准，跳过手动旋钮步骤。
- 未携带时：图纸背面显示目标波形；振幅、频率、相位三个旋钮各有离散档位，实时更新波形。单项正确即锁定亮灯，全部正确后可启动。
- 不根据当前理智数值额外设门槛；跳过只检测实际上游道具 ID。
- 实际上游 ID 尚未提供。开发配置使用明确的待替换常量，发布检查必须阻止待替换值进入正式包；不得冒用示例“启程火炬”ID。

### 5.5 启动与结尾（目标约 20 秒）

- 第一次闪光前，客人像经历过一样提前移开视线。
- 主角进入传送门，客人只说：“欢迎下次光临。”
- 最后镜头停在柜台：陌生硬币纹样与图纸目的地印记相同，不解释客人身份。
- 不展示门后场景。

固定结束语：

> 主角踏入未知的光，身后那声“欢迎下次光临”还未散去，柜台上的陌生硬币正映出目的地的印记……

## 6. 操作、提示与防卡死

- 所有拖放均有“点击物品，再点击目标”的替代路径。
- 图纸固定为可点击入口，装配和调频时可放大对照。
- 关键物品不可丢弃；咖啡胶囊、组件和导管不会因误操作永久消失。
- 密码、装配、接线和调频分别可重试或重置，不清空其他阶段。
- 无误操作扣血，无可见倒计时。
- 停滞约 20 秒：高亮相关区域；45 秒：提示线索关系；75 秒：高亮下一具体对象。
- 提示按当前阶段和有效交互重置，不自动完成谜题。
- 菜单“放弃本次夜班”使用游戏内二次确认，确认后调用失败交接。

## 7. 场景与视听

### 营业区

左侧货架和价签，中间柜台、客人、收银机和咖啡机，右侧仓库门。暖色日常照明，关键商品和文字在大屏上清晰可见。

### 仓库

门框居中，组件和导管位于两侧，冷暗照明。传送门启动后冷光逐渐侵入营业区，结尾再切回柜台硬币特写。

### 声音

城市风声、冰箱低鸣、远处车流作为环境底音；扫码、咖啡机、小票、机械锁、接合和启动提供操作反馈。启动时加入原创低频氛围音乐。所有听觉信息都有视觉等价反馈，不使用商业音乐。

## 8. 交接数据

- A 轨从 `WL.readSave()` 获取存档，并监听 `iw-save-ready`、`iw-admin` 更新实际状态。iframe 中首份有效存档到达前只显示接档状态，不挂载玩法；挂载后收到更新时通过场景更新接口同步，不重挂载、不清空谜题进度。
- 玩法不扣血或修改理智；提交真实游玩结束时的存档。
- 成功：`WL.completeLevel(window.CONFIG || {}, save, { acquiredItemIds: [], exitHook: EXIT_HOOK })`。
- 正式 iframe 中官方协议会优先采用 `window.CONFIG.exitHook`，因此大厅和 `mock-runner.html` 的结束语配置必须与 `EXIT_HOOK` 完全一致；模块内常量只是独立运行和测试的兜底。
- 放弃：`WL.failLevel("主角结束了这次未完成的夜班", save, window.CONFIG || {})`。
- `global-items.json` 使用空声明；不得保留示例关东煮。

## 9. 留给实现者的细节

以下不改变已确认玩法，可由实现者按本计划接口完成：

- 手绘素材的具体笔触、组件外形和传送门动画帧。
- 波形绘制方式与旋钮具体视觉，只要离散调节、单项锁定和图纸目标清晰。
- 提示文案的措辞，只要按 20/45/75 秒逐级具体化。
- 环境音和原创氛围音乐的具体编配。
- 无依赖 DOM/SVG 组件内部实现与 CSS 动画细节。

实现前唯一必须补齐的外部资料：上一关真实交接声明及理智遗物 ID。其他开发任务可以先并行进行。
